## RAG 多路径召回 Micrometer 监控埋点

**问**：如何为多路径 RAG 检索的 joined / reranked 阶段埋点？指标含义与告警思路是什么？

**答**：

- **指标名称**：`springai.rag.pgvector.recall.path.hits`（Counter）
- **标签**：`operation`（操作类型）、`stage`（`joined` 合并去重后 / `reranked` LLM Rerank 后）
- **监控价值**：
  - `joined`：进入候选池的文档数，反映检索效率。
  - `reranked`：Rerank 后保留数；若经常为 0 说明检索质量差。
  - 可统计 Rerank 保留率 = reranked / joined。

**代码示例**：

```java
private static final String RECALL_PATH_HITS = "springai.rag.pgvector.recall.path.hits";

// joined 阶段（合并去重后）
Counter.builder(RECALL_PATH_HITS)
    .tag("operation", operation)
    .tag("stage", "joined")
    .register(meterRegistry)
    .increment(joinedCount);

// reranked 阶段（LLM Rerank 后）
Counter.builder(RECALL_PATH_HITS)
    .tag("operation", operation)
    .tag("stage", "reranked")
    .register(meterRegistry)
    .increment(rerankedCount);
```

**Prometheus 查询示例**：

```promql
# 平均 joined 阶段文档数
avg(springai_rag_pgvector_recall_path_hits_total{stage="joined"})

# Rerank 保留率
sum(springai_rag_pgvector_recall_path_hits_total{stage="reranked"}) /
sum(springai_rag_pgvector_recall_path_hits_total{stage="joined"})
```

**告警规则示例**：

```yaml
- alert: RAGRetrievalEmpty
  expr: |
    increase(springai_rag_pgvector_recall_path_hits_total{stage="reranked"}[5m]) == 0
  annotations:
    summary: "RAG 检索连续5分钟返回空结果"
```

## RAG 可观测性 Metrics 与 Tracing

**问**：生产环境如何对 RAG 各环节进行可观测性埋点？请说明 Micrometer Tracing 和核心指标。

**答**：

- **链路追踪**：用 Micrometer Tracing 为 retrieve、embed、rerank、generate 等步骤创建 Span，打 tag（query、topK）。
- **核心指标**：检索延迟（Timer）、Top-K 命中率（Counter）、重排精度提升（Gauge）、缓存命中率、Token 消耗。

**代码示例**：

```java
@Autowired
private Tracer tracer;

public List<Document> retrieveWithTrace(String query) {
    Span span = tracer.nextSpan().name("vectorstore.similaritySearch").start();
    try (Tracer.SpanInScope ws = tracer.withSpanInScope(span)) {
        span.tag("query", query);
        span.tag("topK", String.valueOf(topK));
        return vectorStore.similaritySearch(SearchRequest.query(query).withTopK(topK));
    } catch (Exception e) {
        span.error(e);
        throw e;
    } finally {
        span.end();
    }
}
```

## Ragas 框架是什么

**问**：Ragas 是什么？核心价值有哪些？

**答**：

- **定义**：Ragas 是开源 Python 框架，专门用于**评估和优化 RAG 应用**，将 AI 系统性能评估从主观判断转化为数据驱动流程。
- **无参考评估**：支持 reference-free，无需人工标注标准答案，直接用 LLM 作为评审员。

**核心价值**：

- **无参考评估**：自动评估 RAG 检索与生成各环节。
- **快速定位瓶颈**：区分检索（Retrieval）还是生成（Generation）的问题。
- **合成测试集生成**：根据文档库自动生成问答对，降低标注成本。

## Ragas 评估指标体系

**问**：Ragas 提供哪些核心评估指标？分别衡量什么？

**答**：

| 环节 | 指标 | 说明 |
| :--- | :--- | :--- |
| 检索器 | 上下文精度 (Context Precision) | 检索文档的信噪比，衡量结果是否精准 |
| 检索器 | 上下文召回率 (Context Recall) | 关键信息覆盖率，判断是否遗漏重要内容 |
| 生成器 | 忠实度 (Faithfulness) | 回答是否完全基于检索上下文，**减少幻觉** |
| 生成器 | 答案相关性 (Answer Relevancy) | 回答是否切题、简洁 |
| 端到端 | 答案正确性 (Answer Correctness) | 与标准答案（若有）比对，评估最终效果 |

## Ragas 快速上手

**问**：如何使用 Ragas 对 RAG 系统进行评测？请给出完整代码示例。

**答**：

1. 安装 `pip install ragas`。
2. 构造测试数据：`question`、`answer`（RAG 回答）、`contexts`（检索上下文列表）。
3. 选择指标并调用 `evaluate()`，输出 0~1 得分。

**代码示例（安装）**：

```bash
pip install ragas
```

**代码示例（准备数据与运行评测）**：

```python
from datasets import Dataset
from ragas import evaluate
from ragas.metrics import faithfulness, answer_relevancy, context_precision

data = {
    "question": ["什么是 RAG？", "Ragas 框架能做什么？"],
    "answer": [
        "RAG 是检索增强生成，结合检索和生成模型。",
        "Ragas 可以评估 RAG 系统的检索和生成质量。"
    ],
    "contexts": [
        ["RAG 结合了信息检索和文本生成技术。"],
        ["Ragas 提供忠实度、答案相关性等评估指标。"]
    ]
}

dataset = Dataset.from_dict(data)

result = evaluate(
    dataset,
    metrics=[faithfulness, answer_relevancy, context_precision]
)

print(result)
```

## Ragas 结果分析与瓶颈定位

**问**：如何根据 Ragas 指标得分定位 RAG 系统问题？

**答**：

- **faithfulness 低** → 生成模型产生幻觉，需优化 prompt 或检索内容质量。
- **context_precision 低** → 检索带回过多噪音，需调整检索策略（TopK、重排、混合检索等）。
- **answer_relevancy 低** → 回答偏离问题，可改进生成提示词。
- **context_recall 低** → 关键信息遗漏，需优化分块、召回路数或索引。

## Ragas 与 Spring AI CI 集成

**问**：如何在 Spring AI 应用中集成 Ragas 评估框架？请给出 CI 流水线设计思路。

**答**：

- **架构**：独立 Python Ragas 服务（Docker 化），Spring 应用通过 HTTP 异步提交评测数据。
- **CI 流程**：启动测试环境 → 部署 Spring AI 应用 → 测试集遍历 → 调用 Ragas 服务 → 评估指标 → 质量门禁（如 `context_recall >= 0.85`）。

**代码示例（Python 质量门禁）**：

```python
# ragas_evaluator.py
def evaluate_and_check():
    result = evaluate(test_dataset, metrics=[context_recall])
    assert result["context_recall"] >= 0.85, "召回率过低！"
```

## Prometheus 与 Grafana 监控大盘

**问**：在 Spring AI 中如何基于 Micrometer 为 RAG 链路建立性能基准和监控大盘？

**答**：

- 添加 `micrometer-registry-prometheus` 依赖，暴露 `/actuator/prometheus` 端点。
- **关键指标**：`gen_ai_client_operation_seconds`、`db_vector_client_operation_seconds`、`ai.rag.relevancy.score`。
- 在检索方法用 Timer 记录 P95/P99，Grafana 做端到端延迟与召回质量大盘。

**代码示例**：

```java
@Bean
public MeterRegistryCustomizer<MeterRegistry> metricsConfig() {
    return registry -> registry.config().commonTags("application", "rag-service");
}

// 在检索方法中
Timer.Sample sample = Timer.start(registry);
// 执行检索...
sample.stop(Timer.builder("vectorstore.search.duration")
    .publishPercentiles(0.99, 0.95)
    .register(registry));
```
