## 异步并行检索与超时控制

> **模块**：性能与高可用 | **标签**：性能与高可用 | **更新**：2026-05-28

### 核心概念

用 `@Async` 或 `CompletableFuture` 并行查询多个 VectorStore/分区。

### 要点

- 用 `@Async` 或 `CompletableFuture` 并行查询多个 VectorStore/分区。
- 用 `CompletableFuture.allOf` 合并结果。
- 配合 `orTimeout(2, SECONDS)` 与 `exceptionally` 返回空列表，避免慢路径拖垮整请求。

### 代码示例

```java
@Service
public class ParallelRetrievalService {
    @Async("vectorSearchExecutor")
    public CompletableFuture<List<Document>> searchFromStore1(String query, int topK) {
        List<Document> docs = vectorStore1.similaritySearch(
            SearchRequest.query(query).withTopK(topK)
        );
        return CompletableFuture.completedFuture(docs);
    }
}

// 合并与超时
CompletableFuture<List<Document>> future1 = parallelService.searchFromStore1(query, 20);
CompletableFuture.allOf(future1, future2, future3).orTimeout(2, TimeUnit.SECONDS).join();
```

### 面试常问

**问**：如何通过异步并行检索和结果流式处理优化端到端延迟？结合 CompletableFuture 给出设计思路。

**答**：用 `@Async` 或 `CompletableFuture` 并行查询多个 VectorStore/分区。；用 `CompletableFuture.allOf` 合并结果。；配合 `orTimeout(2, SECONDS)` 与 `exceptionally` 返回空列表，避免慢路径拖垮整请求。。

## ChatClient 响应 @Cacheable 缓存

> **模块**：性能与高可用 | **标签**：性能与高可用 | **更新**：2026-05-28

### 核心概念

适用场景：FAQ、固定模板问答等重复 prompt 占比高的场景。

### 要点

- **适用场景**：FAQ、固定模板问答等重复 prompt 占比高的场景。
- **实现**：在 Service 层用 Spring `@Cacheable`，以 prompt 为 key 缓存返回字符串。
- **注意**：时效性查询（含日期、实时数据）应通过 `condition` 排除；设置合理 TTL 避免 stale 答案。

### 代码示例

```java
@Cacheable(value = "aiResponses", key = "#prompt")
public String getCompletion(String prompt) {
    return chatClient.prompt(prompt).call().content();
}
```

### 面试常问

**问**：如何为 ChatClient 相同 prompt 的补全结果引入缓存，降低重复调用成本？

**答**：适用场景**：FAQ、固定模板问答等重复 prompt 占比高的场景。；实现**：在 Service 层用 Spring `@Cacheable`，以 prompt 为 key 缓存返回字符串。；注意**：时效性查询（含日期、实时数据）应通过 `condition` 排除；设置合理 TTL 避免 stale 答案。。

## CompletableFuture 检索超时

> **模块**：性能与高可用 | **标签**：性能与高可用 | **更新**：2026-05-28

### 核心概念

用 `supplyAsync` 包装 vectorSearch，链式 `orTimeout(2, TimeUnit.SECONDS)`，`exceptionally` 记录日志并返回 `Collections.emptyList()`，保证主链路在 SLA 内返回。

### 要点

用 `supplyAsync` 包装 vectorSearch，链式 `orTimeout(2, TimeUnit.SECONDS)`，`exceptionally` 记录日志并返回 `Collections.emptyList()`，保证主链路在 SLA 内返回。

### 代码示例

```java
CompletableFuture<List<Document>> future = CompletableFuture
    .supplyAsync(() -> vectorSearch(query))
    .orTimeout(2, TimeUnit.SECONDS)
    .exceptionally(ex -> {
        log.warn("检索超时", ex);
        return Collections.emptyList();
    });
```

### 面试常问

**问**：如何用 CompletableFuture 设置超时，防止慢召回拖垮请求？

**答**：用 `supplyAsync` 包装 vectorSearch，链式 `orTimeout(2, TimeUnit.SECONDS)`，`exceptionally` 记录日志并返回 `Collections.emptyList()`，保证主链路在 SLA 内返回。
