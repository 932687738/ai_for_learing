> **模块**：性能与高可用 | **标签**：性能与高可用 | **更新**：2026-05-28

### 要点

用 `supplyAsync` 包装 vectorSearch，链式 `orTimeout(2, TimeUnit.SECONDS)`，`exceptionally` 记录日志并返回 `Collections.emptyList()`，保证主链路在 SLA 内返回。

### 代码示例

```java
CompletableFuture<List<Document>> future = CompletableFuture
    .supplyAsync(() -> vectorSearch(query))
    .orTimeout(2, TimeUnit.SECONDS)
    .exceptionally(ex -> {
        log.warn("检索超时", ex);
        return Collections.emptyList();
    });
```

## 路由降级与高可用机制

> **模块**：性能与高可用 | **标签**：路由, 降级, Fallback, 熔断 | **更新**：2026-06-06

### 核心概念

路由为请求选择最优处理路径（模型/Agent/工具）；降级在主路径故障、超时或限流时自动切换备用路径，保障服务不中断，常由 AI 网关统一实施。

### 要点

**路由维度**：任务复杂度、语义意图、业务规则与成本；LangGraph 条件边、LLM Router 实现。

**降级策略**：
- 主备模型切换（Resilience4j 熔断+fallbackMethod）
- 多级链路：云端高质量 → 本地备用 → 缓存答案 → 人工队列
- 静默降级：配额用尽时无感切换 mini 模型

**原则**：统一接入层、策略可配置、高风险任务谨慎降级、全链路可观测（路由决策、降级原因、Token/耗时）。

### 面试常问

**问**：AI Agent 系统中路由降级是什么？如何实现？

**答**：路由选最优路径，降级在主路径失败时切备用模型/工具/缓存/人工。通过网关集中配置规则与 fallback 链，结合熔断重试与监控，区分业务风险决定是否允许降级。
