## similaritySearch 与 similarityThreshold 对比

> **模块**：索引与存储 | **标签**：索引与存储 | **更新**：2026-05-28

### 核心概念

文档 1「猫咪需要高蛋白食物」→ 0.92；文档 2「猫咪喜欢睡觉」→ 0.35；文档 3「狗狗需要运动」→ 0.12

### 要点

**核心区别**：

| 特性 | similaritySearch（无阈值） | similarityThreshold（带阈值） |
| :--- | :--- | :--- |
| 核心理念 | 数量优先，保证返回 topK 条 | 质量优先，只返回超过阈值的结果 |
| 返回数量 | **固定为 K**（低分也可能被返回） | **不固定**（可能少于 K，甚至为 0） |
| 文档质量 | 可能混入不相关内容 | 阈值过滤，结果更精准 |
| 典型场景 | 对数量有硬性要求，或需二次过滤 | 对准确性要求高，避免低质量噪声 |

**举例**（检索「猫咪吃什么比较好？」）：

- 文档 1「猫咪需要高蛋白食物」→ 0.92；文档 2「猫咪喜欢睡觉」→ 0.35；文档 3「狗狗需要运动」→ 0.12
- **topK=2 无阈值**：返回文档 1、2（为凑够数量，低分文档 2 也被返回）
- **阈值=0.7**：仅返回文档 1；即使 topK=10 也只返回 1 条

**常量 `SIMILARITY_THRESHOLD_ACCEPT_ALL`**：值为 `0.0`，接受所有文档（得分 ≥ 0），效果等同于普通 `similaritySearch`。

### 代码示例

```java
SearchRequest request = SearchRequest.query("用户问题")
        .withTopK(5)
        .withSimilarityThreshold(SearchRequest.SIMILARITY_THRESHOLD_ACCEPT_ALL);

List<Document> results = vectorStore.similaritySearch(request);
```

```java
SearchRequest request = SearchRequest.query("用户问题")
        .withTopK(10)
        .withSimilarityThreshold(0.75);

List<Document> results = vectorStore.similaritySearch(request);
```

### 面试常问

**问**：Spring AI VectorStore 中 `similaritySearch` 与基于 `similarityThreshold` 的检索有何区别？`SIMILARITY_THRESHOLD_ACCEPT_ALL` 是什么？

**答**：文档 1「猫咪需要高蛋白食物」→ 0.92；文档 2「猫咪喜欢睡觉」→ 0.35；文档 3「狗狗需要运动」→ 0.12；topK=2 无阈值**：返回文档 1、2（为凑够数量，低分文档 2 也被返回）；阈值=0.7**：仅返回文档 1；即使 topK=10 也只返回 1 条。

## VectorStore 相似度搜索与元数据过滤

> **模块**：索引与存储 | **标签**：索引与存储 | **更新**：2026-05-28

### 核心概念

通过 `SearchRequest` 的 `withFilterExpression` 传入 `Filter.Expression` 组合条件，配合 `withTopK(5)` 与 `withSimilarityThreshold` 发起检索。

### 要点

通过 `SearchRequest` 的 `withFilterExpression` 传入 `Filter.Expression` 组合条件，配合 `withTopK(5)` 与 `withSimilarityThreshold` 发起检索。

### 代码示例

```java
Filter.Expression filter = Filter.Expression.and(
    Filter.Expression.eq("category", "technology"),
    Filter.Expression.gt("score", 0.7)
);

SearchRequest searchRequest = SearchRequest.query("人工智能")
    .withTopK(5)
    .withSimilarityThreshold(0.5)
    .withFilterExpression(filter);

List<Document> results = vectorStore.similaritySearch(searchRequest);
```

**答**：通过 `SearchRequest` 的 `withFilterExpression` 传入 `Filter.Expression` 组合条件，配合 `withTopK(5)` 与 `withSimilarityThreshold` 发起检索。

## 向量索引优化 HNSW 与 IVFFlat

> **模块**：索引与存储 | **标签**：索引与存储 | **更新**：2026-05-28

### 核心概念

HNSW：低延迟、高召回，内存占用大，适合在线检索。

### 要点

- **HNSW**：低延迟、高召回，内存占用大，适合在线检索。
- **IVF / IVFFlat**：内存友好、构建快，需训练，召回略低。
- **DiskANN**：SSD 场景下平衡延迟与容量。
- **PgVector**：可设 `index-type: HNSW`，调 `m`、`ef_construction`。
- **Redis**：可选 `Algorithm.HNSW`，配置 `hnswM`、`hnswEfConstruction`。

### 代码示例

```yaml
spring:
  ai:
    vectorstore:
      pgvector:
        index-type: HNSW
        distance-type: COSINE_DISTANCE
        dimensions: 1536
```

```java
RedisVectorStore vectorStore = RedisVectorStore.builder(jedisPooled, embeddingModel)
    .indexName("my_vector_index")
    .vectorAlgorithm(Algorithm.HNSW)
    .hnswM(32)
    .hnswEfConstruction(200)
    .build();
```

### 面试常问

**问**：如何利用索引类型选择（HNSW、IVF_FLAT）以及分区/分片策略优化检索性能？请结合 Milvus、PgVector 或 Redis 给出配置建议。

**答**：HNSW**：低延迟、高召回，内存占用大，适合在线检索。；IVF / IVFFlat**：内存友好、构建快，需训练，召回略低。；DiskANN**：SSD 场景下平衡延迟与容量。；PgVector**：可设 `index-type: HNSW`，调 `m`、`ef_construction`。。

## 多租户数据隔离

> **模块**：索引与存储 | **标签**：索引与存储 | **更新**：2026-05-28

### 核心概念

写入：在 metadata 强制注入 `tenant_id`。

### 要点

- **写入**：在 metadata 强制注入 `tenant_id`。
- **检索**：用 `Filter.ExpressionBuilder.eq("tenant_id", currentTenantId)` 与 SearchRequest 组合，确保仅命中本租户数据。

### 代码示例

```java
// 插入时强制注入 tenant_id
public void addDocument(String content, Map<String, Object> extraMetadata) {
    String tenantId = tenantSecurityUtil.getCurrentTenantId();
    Map<String, Object> metadata = new HashMap<>(extraMetadata);
    metadata.put("tenant_id", tenantId);
    Document doc = new Document(content, metadata);
    vectorStore.add(List.of(doc));
}

// 检索时动态过滤
public List<Document> searchByTenant(String query, int topK) {
    String tenantId = tenantSecurityUtil.getCurrentTenantId();
    Filter.Expression tenantFilter = Filter.ExpressionBuilder.eq("tenant_id", tenantId);
    SearchRequest searchRequest = SearchRequest.query(query)
            .withTopK(topK)
            .withFilterExpression(tenantFilter);
    return vectorStore.similaritySearch(searchRequest);
}
```

### 面试常问

**问**：如何利用元数据过滤实现租户级别的数据隔离？请给出插入和检索时的代码示例。

**答**：写入**：在 metadata 强制注入 `tenant_id`。；检索**：用 `Filter.ExpressionBuilder.eq("tenant_id", currentTenantId)` 与 SearchRequest 组合，确保仅命中本租户数据。。

SimpleVectorStore：内存存储，数据易失，适合开发测试。

### 要点

- **SimpleVectorStore**：内存存储，数据易失，适合开发测试。

```yaml
spring:

        index-type: HNSW
        distance-type: COSINE_DISTANCE
```

## Elasticsearch 分片与副本策略

> **模块**：索引与存储 | **标签**：索引与存储 | **更新**：2026-05-28

### 核心概念

分片键：合理选择 routing 字段，避免热点分片。

### 要点

- **分片键**：合理选择 routing 字段，避免热点分片。
- **分片大小**：单分片建议 10GB–50GB，过多小分片增加协调开销。
- **副本**：增加副本数提升读吞吐与可用性，但占用更多存储。
- **refresh_interval**：适当调大（如 30s）降低写入压力，检索场景可权衡实时性。

### 代码示例

```yaml
# Elasticsearch 索引配置示例
settings:
  number_of_shards: 3
  number_of_replicas: 1
  index:
    refresh_interval: 30s
```

### 面试常问

**问**：Elasticsearch 向量索引如何配置分片与副本以优化检索吞吐？

**答**：分片键**：合理选择 routing 字段，避免热点分片。；分片大小**：单分片建议 10GB–50GB，过多小分片增加协调开销。；副本**：增加副本数提升读吞吐与可用性，但占用更多存储。；refresh_interval**：适当调大（如 30s）降低写入压力，检索场景可权衡实时性。。

## Elasticsearch routing 精确查找

> **模块**：索引与存储 | **标签**：索引与存储 | **更新**：2026-05-28

### 核心概念

写入侧：在 `@Document` 或映射中指定 `routing` 字段（如 `customerId`），使同一租户/客户文档落在同一分片。

### 要点

- **写入侧**：在 `@Document` 或映射中指定 `routing` 字段（如 `customerId`），使同一租户/客户文档落在同一分片。
- **查询侧**：`SearchRequest` 携带相同 routing 值，检索仅命中目标分片。
- **收益**：缩小搜索范围、降低延迟，适合多租户或按业务键分区场景。

### 代码示例

```java
@Document(indexName = "orders", routing = "customerId")
public class Order { ... }

SearchRequest request = SearchRequest.of(q -> q
    .index("orders")
    .routing("cust_123")
    .query(...)
);
```

### 面试常问

**问**：如何利用 Elasticsearch routing 减少跨分片扫描、加速精确查找？

**答**：写入侧**：在 `@Document` 或映射中指定 `routing` 字段（如 `customerId`），使同一租户/客户文档落在同一分片。；查询侧**：`SearchRequest` 携带相同 routing 值，检索仅命中目标分片。；收益**：缩小搜索范围、降低延迟，适合多租户或按业务键分区场景。。
